# 골목컵 개발 계획 (v1.0)

작성 2026-11-02 · 기준 문서: [게임 기획서](golmok-cup-gdd.md)
전제: **Godot 4**, 소규모 팀(1–3명 + Claude), 11대11 정식 축구, 2D 픽셀아트 아케이드 스타일

---

## 1. 팀과 역할

| 역할 | 담당 | 비고 |
|---|---|---|
| 리드 개발·기획 | 사용자 (1명) | 방향 결정, 손맛 튜닝, 플레이테스트 |
| 코드·툴·데이터 | Claude | 게임플레이 코드, 에디터 툴, 데이터 파이프라인, 테스트, 문서 |
| 픽셀 아트 | 외주 또는 파트타임 1명 | M1 말부터 투입. 그 전에는 임시 도트 사용 |
| (선택) QA·기획 보조 | 파트타임 1명 | M3부터 |
| 사운드 | 외주 / 에셋 구매 | M3 |

**월 투입 가정**: 리드 1.0 MM + 아트 0.5–1.0 MM + 기타 0.3 MM

## 2. 기술 구조

### 2.1 스택
| 영역 | 선택 | 이유 |
|---|---|---|
| 엔진 | Godot 4.x 최신 안정판 | 가벼운 2D, 라이선스 비용 없음, 모바일·데스크톱 내보내기 |
| 언어 | GDScript (정적 타입 사용). 병목이 생기면 해당 부분만 C++ GDExtension | 반복 속도 우선 |
| 렌더링 | 2D, 640×360 뷰포트, 정수 스케일, Nearest 필터, 팔레트 교체 셰이더 | 픽셀 정확도 |
| 물리 | **Godot 물리 엔진을 쓰지 않고** 2.5D 자체 시뮬레이션 (60Hz 고정 틱) | 원작 방식 재현, 결정론(리플레이·향후 온라인) |
| 데이터 | JSON (팀·선수·포메이션·대회·바닥·스킬) → 로드 시 Resource 변환 | 사람이 편집하기 쉽고, 에디터 툴과 공유 가능 |
| 저장 | `user://` JSON + 체크섬 | 단순함 |
| 입력 | InputMap + 자체 가상 패드(터치) | 패드·키보드·터치 통합 |
| 테스트 | GUT(유닛 테스트) + 헤드리스 시뮬레이션 테스트 | 물리·규칙 회귀 방지 |
| 버전 관리 | Git + Git LFS(아트), GitHub Actions로 헤드리스 테스트·내보내기 | |

### 2.2 프로젝트 구조
```
golmok-cup/
├─ sim/            # 결정론 시뮬레이션 (렌더링과 분리, 노드 의존 없음)
│  ├─ physics/     # Body2_5D, 적분기, 바운드, 충돌(원·캡슐)
│  ├─ match/       # MatchState, 규칙, 심판, 세트피스, 시계
│  ├─ player/      # 선수 상태 머신, 능력치 계산, 스킬
│  ├─ ai/          # 팀 AI, 결정 트리, 포메이션
│  └─ rng.gd       # 시드 고정 난수 (리플레이용)
├─ view/           # 스프라이트, 애니메이션, 카메라, 파티클, HUD
├─ input/          # 컨트롤러 추상화, 가상 패드
├─ modes/          # 친선, 토너먼트, 커리어, 연습
├─ data/           # teams/*.json, formations.json, floors.json, skills.json …
├─ tools/          # 에디터 플러그인: AI 트리 뷰어, 튜닝 패널, 팀 에디터
└─ tests/
```

**핵심 원칙: 시뮬레이션과 화면의 분리.** `sim/`은 입력과 시드만 받아 같은 결과를 내는 순수 로직입니다. `view/`는 그 상태를 그리기만 합니다. 이렇게 하면 다음이 가능합니다.
- 리플레이: 입력만 기록해 다시 재생
- 헤드리스 테스트: 화면 없이 AI 대 AI 경기 수천 판을 돌려 밸런스 측정
- 향후 온라인 롤백 넷코드

### 2.3 물리 기준값 (출발점)
[원작 수치 분석](pixel-cup-soccer-tuning.md)을 기준점으로 삼아 **자체 값**으로 시작하고 M1에서 튜닝합니다.

| 항목 | 출발값 | 원작 참고 |
|---|---|---|
| 틱 | 60Hz 고정 | 원작은 가변 dt |
| 경기장 | 2400 × 1400 | 약 2450 × 1370 |
| 선수 최고 속도 | 190–240 (능력치 보간) | 205–225 |
| 공 중력 / 선수 중력 | −320 / −800 | 같음 |
| 공중 마찰 | 1.0 | 같음 |
| 지면 마찰 (초당) | 0.75 | 0.965 |
| 바운드 Z 손실 | 0.65 | 바닥별 0.5–0.75 |
| 바운드 XY 손실 | 0.65 → 0.40 | 바닥별 |
| 슛 수평 세기 | 400–920 (차지 단계별) | 375–900 |
| 차지 실축 시작 | 1.0초 | 1.05초 |

## 3. 마일스톤

전체 **약 40주(9–10개월)**. 각 마일스톤 끝에 플레이 가능한 빌드와 검토 회의를 둡니다.

### M0. 기반 (2주)
- Godot 프로젝트, 폴더 구조, CI(헤드리스 테스트), 픽셀 렌더 파이프라인
- `sim/physics`: 2.5D 바디, 적분기, 공 바운드·구름, 고정 틱 루프
- 디버그 오버레이: 속도 벡터, 공 높이, 그림자, 틱 카운터
- **완료 기준**: 화면에서 공을 차고 튕기는 테스트 장면. 물리 유닛 테스트 통과

### M1. 코어 경기 프로토타입 (8주) ⭐ 가장 중요
- 선수 이동·드리블·차지 패스/슛·태클·선수 전환
- 11대11 포메이션 이동(공 위치 기반 대형), 기본 AI(공 쫓기, 패스, 슛)
- GK 기본(위치 잡기, 다이빙, 캐치)
- 규칙: 킥오프, 골, 아웃(스로인·코너·골킥), 전후반, 시계
- 카메라 추적, 임시 도트 스프라이트, 최소 HUD
- **튜닝 툴**: 게임 실행 중 물리·차지 값을 슬라이더로 바꾸는 패널
- **완료 기준**: 3분 경기를 끝까지 할 수 있음. 사내 테스터 5명 이상 중 70%가 "한 판 더"
- **중단 판단**: 손맛이 나오지 않으면 M2로 가지 않고 2주 추가 튜닝

### M2. 경기 완성 (9주)
- 반칙 판정(파울·카드·부상), 프리킥 수비벽, 페널티킥, 오프사이드
- 심판·선심 개체, 교체, 체력·부상
- 결정 트리 AI 완성(팀 성향·전술 4종), GK 고급(뛰쳐나가기, 펀칭)
- 스킬 시스템 + 1차 스킬 15종, 슈퍼슛·슈퍼 세이브
- 날씨(비·눈·바람), 바닥 5종, 장애물 3종, 돌발 사건 2종
- 리플레이(입력 기록 재생), 골 연출, 미니맵
- **정식 픽셀 아트 1차**: 선수 공용 스프라이트 세트, 경기장 2곳, UI 기본
- **헤드리스 밸런스 테스트**: AI 대 AI 1,000경기 → 평균 득점·파울·점유율 리포트
- **완료 기준**: 경기당 평균 득점 2–5골, 파울 2–4회, 카드 0–1장. 크래시 없음

### M3. 모드·콘텐츠 (8주)
- 메인 메뉴, 설정(난이도·경기 시간·보조 옵션·언어), 저장
- 친선전(같은 기기 2인 포함), 승부차기 모드, 연습·튜토리얼
- 토너먼트 엔진: 조별·녹아웃·리그 → 대회 8종
- 팀 데이터 48팀 × 18명 (생성 툴 + 수작업 보정)
- 경기장 8곳, 스킬 30종 완성, 사운드 1차
- **완료 기준**: 처음 실행부터 대회 우승까지 막힘 없이 진행. 외부 베타 30–50명 시작

### M4. 커리어·에디터·폴리시 (8주)
- 동네 클럽 커리어: 시즌 일정, 승격, 경험치 → 능력치·스킬 성장
- 팀 에디터(이름·유니폼·능력치)
- 모바일 조작 다듬기(가상 패드 위치·크기 옵션, 보조 기능)
- 한국어·영어·일본어 현지화
- 성능: 저사양 Android 60fps 목표, 배터리 사용량 점검
- **완료 기준**: 베타 평가 4.0/5 이상, 평균 세션 3경기 이상

### M5. 출시 준비 (5주)
- QA(기기 20종), 버그 수정, 밸런스 마감
- 스토어 페이지·트레일러(게임 내 리플레이 활용), 가격 확정
- 법무 검토(상표, 원작 유사성), 개인정보처리방침
- Android·iOS 제출 → 출시
- **완료 기준**: 치명 버그 0, 스토어 승인

### 출시 이후
| 업데이트 | 내용 | 시점 |

## 5. Claude 활용 방식
- **코드**: 시뮬레이션·AI·규칙·모드 구현, GUT 테스트 작성, 리팩터링
- **툴**: 튜닝 패널, AI 결정 트리 뷰어, 팀 데이터 생성기, 밸런스 리포트 스크립트
- **데이터**: 가상 팀·선수 이름과 능력치 생성, 현지화 문자열 초안
- **분석**: 헤드리스 경기 로그 분석, 원작과 감각 비교(이번 분석에서 쓴 화면 녹화 실측 방식 재사용)
- **사람이 맡을 것**: 손맛 판단, 아트 방향, 최종 밸런스, 출시 결정

## 8. 바로 시작할 일 (첫 2주, M0)
1. Godot 4 프로젝트 생성, 폴더 구조, Git LFS, GitHub Actions 헤드리스 테스트

5. 픽셀 아티스트 섭외 시작 (스타일 테스트: 선수 1명 8방향 달리기)
