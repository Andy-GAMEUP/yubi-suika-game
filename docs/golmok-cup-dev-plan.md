# 골목컵 개발 계획 (v2.0 — 무료 플레이·온라인 기준)

작성 2026-11-02 · 기준 문서: [게임 기획서](golmok-cup-gdd.md)
전제: **Godot 4**, 11대11 정식 축구, 2D 픽셀아트 아케이드 스타일, **무료 플레이 BM**(선수 덱 뽑기, 카드 강화 RPG, FA 에이전트 마켓, 온라인 티어전·대전 티켓, 월간 티어 토너먼트)

> v1.0(유료 앱, 서버 없음, 40주)에서 바뀐 점: 서버·온라인 대전·결제·마켓·운영 도구가 추가되어 **인원 +1–2명, 소프트런칭까지 약 49주, 정식 출시까지 약 14개월**로 늘었습니다. 출시 후 라이브 운영 인력과 서버비가 계속 듭니다.

## 2. 기술 구조

### 2.1 전체 구성
```
[Godot 클라이언트]  ── 실시간 대전 입력 ──▶  [Nakama 매치 릴레이]  ◀── 상대 클라이언트
     │  RPC (HTTPS/WebSocket)                         │
     ▼                                                ▼
[Nakama 서버 모듈 (TypeScript 또는 Go)]
  계정 · 지갑(재화) · 인벤토리(카드) · 뽑기 · 강화 · 마켓
  매칭 · 티어 · 시즌 · 토너먼트 · 우편함 · 결제 영수증 검증
     │
     ▼
[PostgreSQL]  거래·뽑기·결제 로그     [헤드리스 Godot 검증 서버]  랭크 경기 결과 재현 검증
     │
[운영 도구]  확률표·상품·이벤트 관리, 이상 거래 탐지, 제재, 보상 지급, 지표 대시보드
```

### 2.2 스택
| 영역 | 선택 | 이유 |
|---|---|---|
| 클라이언트 | Godot 4.x 최신 안정판, GDScript(정적 타입) + 필요 시 C++ GDExtension | 기존 결정 유지 |
| 게임 백엔드 | **Nakama** (오픈소스, 자체 호스팅 또는 관리형) | Godot SDK 공식 지원. 계정·지갑·저장소·매치메이킹·리더보드·토너먼트·결제 검증 기본 제공 → 소규모 팀의 서버 작업량을 크게 줄임 |
| 서버 로직 | Nakama 런타임 모듈 (TypeScript 우선, 성능 필요 시 Go) | 뽑기·마켓 같은 핵심 로직을 서버에서 판정 |
| DB | PostgreSQL (Nakama 기본 지원) | 마켓·재화 이동을 트랜잭션으로 처리 |
| 실시간 대전 | 입력 교환 방식(lockstep) + Nakama 매치 릴레이 → 필요 시 롤백 | 아래 2.3절 |
| 결제 | Google Play Billing, StoreKit 2 → 서버에서 영수증 검증 후 지급 | 결제 위조 방지 |
| 인프라 | 클라우드 1개 리전(서울)에서 시작, 컨테이너 배포 | |
| 분석 | 이벤트 로그 → 대시보드 (리텐션, 결제, 뽑기, 마켓, 대전) | |

### 2.3 실시간 대전 방식 (가장 큰 기술 리스크)
| 방식 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **결정론 lockstep + 입력 지연** (각 기기가 같은 시뮬레이션을 돌리고 입력만 주고받음) | 트래픽 적음, 서버는 중계만, 리플레이·검증 쉬움 | 입력 지연 3–5프레임(50–80ms), **모든 기기에서 계산 결과가 정확히 같아야 함** | **1차 채택** |
| 롤백 넷코드 | 입력 지연 체감 없음 | 22명 + AI를 프레임마다 여러 번 재계산 → 모바일 CPU 부담 큼 | lockstep 결과를 보고 2차 검토 |
| 서버 권위 시뮬레이션 | 치트에 가장 강함 | 서버에서 시뮬레이션 실행 → 서버비 큼, 지연 큼 | 채택 안 함 |

**결정론 확보를 위한 필수 설계**
- 시뮬레이션(`sim/`)은 **고정소수점 정수 연산**으로 작성합니다(예: 1/1000 단위). 실수(float) 연산은 Android(ARM)·iOS·PC 사이에서 결과가 미세하게 달라 lockstep이 깨집니다.
- 난수는 경기 시드 기반 자체 난수기만 사용합니다.
- 매 60틱마다 상태 해시를 교환해 어긋남(desync)을 감지하고 로그를 남깁니다.
- **치트 대응**: 랭크 경기는 양쪽 입력 기록을 서버에 올리고, 결과가 다르게 신고되거나 의심 경기면 헤드리스 Godot 서버가 재현해 판정합니다.

### 2.4 클라이언트 프로젝트 구조
```
golmok-cup/
├─ sim/            # 결정론 시뮬레이션 (고정소수점, 노드 의존 없음)
│  ├─ fixed/       # 고정소수점 수학, 삼각함수 테이블
│  ├─ physics/     # 2.5D 바디, 적분, 바운드, 충돌
│  ├─ match/       # 규칙, 심판, 세트피스, 시계
│  ├─ player/      # 선수 상태 머신, 능력치 계산, 특성
│  └─ ai/          # 팀 AI, 결정 트리, 포메이션
├─ net/            # Nakama 연결, lockstep 입력 교환, 상태 해시, 재접속
├─ meta/           # 클럽, 카드 보관함, 뽑기 화면, 강화, 마켓, 상점, 티어, 토너먼트, 우편함
├─ view/           # 스프라이트, 애니메이션, 카메라, 파티클, HUD
├─ input/          # 컨트롤러 추상화, 가상 패드
├─ data/           # 카드·특성·포메이션·바닥 정의 (서버와 공유하는 JSON)
├─ tools/          # 튜닝 패널, AI 트리 뷰어, 데이터 검증기
└─ tests/          # GUT 유닛 테스트, 헤드리스 경기·결정론 테스트
server/
├─ modules/        # Nakama 런타임: wallet, gacha, cards, market, ranked, tournament, iap, mail
├─ migrations/
├─ admin/          # 운영 도구 웹
└─ tests/
```

### 2.5 서버가 판정해야 하는 것 (클라이언트를 믿지 않음)
| 기능 | 서버 처리 |
|---|---|
| 뽑기 | 서버 난수로 결과 결정, 천장 카운트 저장, 결과 로그 영구 보관 |
| 재화 | 모든 증감은 서버 트랜잭션, 이력 보관 |
| 강화·승급·방출 | 재료 소모와 결과를 한 트랜잭션으로 처리 |
| 마켓 | 등록·구매·정산·수수료·가격 범위 검사를 한 트랜잭션으로 처리, 동시 구매 경합 처리 |
| 대전 결과 | 양쪽 보고 일치 확인, 불일치·이상 시 재현 검증 → 티어 점수 반영 |
| 티켓 | 지급·소모·환불을 서버에서 관리 |
| 결제 | 스토어 영수증 검증 후 지급, 환불 대응(재화 회수) |

### M0. 기반·기술 검증 (4주)
- Godot 프로젝트, CI(헤드리스 테스트), 픽셀 렌더 파이프라인
- `sim/fixed` 고정소수점 수학 + 공 물리(바운드·구름) + 결정론 테스트(Android·iOS·Mac에서 같은 입력 → 같은 해시)
- Nakama 로컬 환경, 계정 생성·로그인, Godot SDK 연결
- **lockstep 실험**: 단순 장면(공 1개 + 선수 2명)을 두 기기에서 입력만 주고받아 동기화
- **완료 기준**: 세 플랫폼 결정론 해시 일치. 4G 환경 입력 지연 80ms 이하로 동기화 유지
- **실패 시**: 시뮬레이션 핵심을 C++ GDExtension으로 옮기는 안 검토(+3주)

### M1. 코어 경기 (8주) ⭐ 손맛 검증
- 이동·드리블·차지 패스/슛·태클·선수 전환, 11대11 포메이션 이동, 기본 AI, GK
- 규칙: 킥오프, 골, 아웃(스로인·코너·골킥), 전후반, 시계
- 카메라, 임시 도트, 최소 HUD, 튜닝 패널
- (서버 개발자) 지갑·인벤토리 기본 모듈, DB 스키마
- **완료 기준**: 3분 경기 완주, 사내 테스터 70% "한 판 더"
- **중단 판단**: 손맛이 안 나오면 2주 추가 튜닝, 그래도 안 되면 방향 재검토

### M2. 경기 완성 + 온라인 1차 (9주)
- 반칙·카드·부상, 프리킥·페널티·오프사이드, 심판·선심, 교체·체력
- 결정 트리 AI 완성, GK 고급, 특성 시스템 + 1차 특성 15종, 슈퍼슛·슈퍼 세이브
- 날씨·바닥·장애물, 리플레이, 골 연출, 미니맵
- 정식 픽셀 아트 1차(선수 공용 세트, 경기장 2곳, UI 기본)
- **온라인**: 매치메이킹(기본), lockstep 11대11 대전, 재접속, desync 감지, 이탈 처리
- 헤드리스 AI 대 AI 1,000경기 밸런스 리포트
- **완료 기준**: 경기당 평균 2–5골·파울 2–4회. 사내 온라인 대전 100경기 중 desync 1% 이하

### M3. 메타·BM (10주)
- 계정(게스트 → 구글·애플 연동), 클럽 생성, 튜토리얼 흐름
- **선수 카드**: 등급 5단계, 능력치·특성·레벨·강화, 카드 보관함, 스쿼드 편성
- **뽑기**: 일반·고급 덱, 확정 보상, 천장, 픽업 덱 구조, 확률 표시 화면, 뽑기 이력
- **강화·승급·방출**, 재료 경제
- **재화·상점**: 골드볼·클럽 코인, 결제(스토어 연동 + 서버 검증), 패키지, 월정액, 시즌 패스 구조
- **대전 티켓**: 일일 10장 지급·소모·구매·환불
- 시즌 리그(PvE, AI 클럽) = 무과금 재화 획득처
- 우편함(보상 지급), 출석·업적
- 카드 데이터: 선수 300명 × 등급별 카드 (생성 툴 + 수작업 보정), 카드 초상(픽셀 머리 + 팔레트 조합)
- **완료 기준**: 신규 계정 → 튜토리얼 → 뽑기 → 강화 → 온라인 대전까지 막힘 없음. 결제 테스트(샌드박스) 통과

### M4. 마켓·티어·토너먼트·운영 (8주)
- **FA 에이전트 마켓**: 등록·검색·구매·정산, 수수료, 시세 기반 가격 범위, 재판매 제한, 거래 불가 카드, 시세 그래프
- **티어·시즌**: 7티어, 점수 규칙, 연승 보너스, 시즌 종료 보상, 시즌 초기화
- **매칭 고도화**: 티어 + 전력 범위, 대기 시간에 따른 범위 확장, AI 대리 경기
- **월간 티어 토너먼트**: 자격 판정, 대진 생성, 라운드 진행·대기·부전패, 보상
- **운영 도구**: 확률표·상품·이벤트 관리, 우편 일괄 지급, 유저 조회·제재, 이상 거래 탐지 리포트, 결제·환불 처리, 지표 대시보드
- **완료 기준**: 내부 테스트 시즌 1회(2주로 압축)를 처음부터 끝까지 진행

### M5. CBT (4주)
- 비공개 테스트 1,000명. 서버 부하, 매칭 대기, desync, 경제(재화 유통량·마켓 시세), 뽑기 체감 확인
- **완료 기준**: 매칭 대기 중앙값 20초 이하, 크래시율 0.5% 이하, 치명 경제 버그 0

### M6. 소프트런칭 준비 (6주)
- CBT 피드백 반영, 밸런스·확률·가격 확정
- 현지화(한·영·일), 저사양 기기 최적화
