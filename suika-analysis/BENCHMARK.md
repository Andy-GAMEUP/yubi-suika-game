## 2. 게임 규칙

### 과일 단계와 점수 (합쳐질 때 *합쳐진 과일 기준*으로 가산)

| 단계 | 스프라이트(px) | 실제 반지름(≈ w×0.75/2) | 점수 |
|---|---|---|---|
| fruit0 | 49×67 | ~18 | 1 |
| fruit1 | 63×68 | ~24 | 3 |
| fruit2 | 88×88 | ~33 | 6 |
| fruit3 | 96×104 | ~36 | 10 |
| fruit4 | 126×133 | ~46 | 15 |
| fruit5 | 164×168 | ~58 | 21 |
| fruit6 | 184×194 | ~68 | 28 |
| fruit7 | 223×220 | ~84 | 36 |
| fruit8 | 251×287 | ~94 | 45 |
| fruit9 | 309×309 | ~116 | 55 |
| fruit10 (수박) | 360×360 | ~135 | 66 |

- 점수 = 삼각수 수열(1,3,6,10,…,66) **[관찰]**
- 수박 + 수박 → 둘 다 사라지고 66점, 새 과일 없음 (`nextUpgrade`가 10이면 null) **[관찰]**
- 드롭 과일: `fruit0~fruit4` 균등 랜덤 **[관찰]**. 첫 과일은 항상 fruit0.
- 드롭 쿨다운 600ms, 다음 과일 미리보기 1개 **[관찰]**
- 합체 시 파티클(flare 5개) + remove 사운드, 새 과일은 bodyA 위치에 생성 **[관찰]**

### 게임오버 판정

서로 *다른* 과일끼리 충돌했을 때 어느 한쪽의 `y − centerOffset.y/2 < 70` 이면 즉시 게임오버 **[관찰]**.
→ 유예 시간이 없어 방금 떨어뜨린 과일이 위쪽에서 다른 과일과 스치기만 해도 게임오버가 날 수 있음 **[추론]**.

### 점수 저장
- 최고점: `localStorage['score']` **[관찰]**
- 서버 랭킹: `POST /score {score, f: 남은 과일 수, t: 플레이 초}` — 클라이언트가 보낸 값을 그대로 전송, 검증 수단 없음 **[관찰/추론]**

## 3. 개선 여지 (벤치마크 시사점)

| 원본의 약점 | 내 버전의 대응 |
|---|---|
| 게임오버 즉시 판정 (유예 없음) | 데드라인 위에 **2초 이상 머무를 때만** 게임오버, 경고 표시 |
| 합체 시 같은 과일 3개가 동시에 닿으면 중복 합체 가능 (`fruits.forEach`로 일괄 destroy, 합체 중 플래그 없음) **[추론]** | `merging` 플래그로 1회만 합체 |
| 과일별 원점/크기 하드코딩(`setFruitSize`, `setFruitOrigin`) | 반지름 테이블 하나로 통일, 과일을 캔버스로 직접 그림 |
| 드롭 가이드 없음 | 낙하 위치 가이드 라인 |
| 마우스 중심 (pointermove/pointerup) | 마우스·터치·키보드(←→/Space) 지원 |
| 콤보 개념 없음 | 연쇄 합체 콤보 보너스 |
| 효과음 wav 파일 | Web Audio로 합성(리소스 0개) |
